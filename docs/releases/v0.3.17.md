# Sentinel 0.3.17

Fix a process-exit race that can abort listener and tool inspection with
`Permission denied during inspection (errno 13)`.

- Linux may return a permission error when a process exits after its descriptor
  link has been resolved. Sentinel now tolerates this only when a subsequent
  process-directory check confirms that the process has disappeared.
- Denials against a live process, and inconclusive rechecks, still make the scan
  unavailable and pause baseline comparison. The service sandbox is unchanged.
- Per-process permission failures identify the operation, PID and FD where
  applicable, without revealing raw exception text, arguments or link targets.
- `/health` retains the last listener-scan failure and timestamp across recovery
  and restart. Historical evidence is labelled separately from current health.

An isolated child-process probe reproduced the kernel behavior on Ubuntu
`6.8.0-142-generic`. The old generic alert did not identify the failed operation,
so it cannot conclusively attribute a historical production failure to this race.
Regression tests cover real Linux procfs behavior, controlled scanner races,
genuine denials and diagnostic persistence. The fix has not been deployed to the
production service during this investigation.

## Upgrade

Download the archive and checksum into the same directory:

```bash
sha256sum --check --strict sentinel-0.3.17.tar.gz.sha256
tar -xzf sentinel-0.3.17.tar.gz
cd sentinel-0.3.17
sudo ./install.sh
```

Then send `/health` and `/selftest`. Only Sentinel restarts; configuration and
credentials are preserved. If a new scan failure occurs, `/health` retains its
operation and numeric process context even after the check recovers.
