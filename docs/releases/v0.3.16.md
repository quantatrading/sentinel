# Sentinel 0.3.16

Monitoring failures now identify their reason and affected coverage.

- File-hashing health is reported independently of listener/tool inspection.
- A failed listener scan no longer falsely reports `security_files` unavailable.
- Baseline comparison reports that it is blocked by the missing inventory instead
  of generating a duplicate failure warning for that dependency.
- Alerts and `/health` include fixed, safe explanations for permissions, resource
  limits, changing files or invalid data. Paths, credentials and raw exception
  text are excluded.
- Fixed the acknowledged-baseline status formatter used by `/status` and `/selftest`.

This corrects reporting and improves diagnosis; it does not assume that a real
permission, capacity or data error has been repaired. Incomplete scans remain
unavailable, and stale/incomplete evidence cannot be approved.

## Upgrade

Download the archive and checksum into the same directory:

```bash
sha256sum --check --strict sentinel-0.3.16.tar.gz.sha256
tar -xzf sentinel-0.3.16.tar.gz
cd sentinel-0.3.16
sudo ./install.sh
```

Then send `/health` and `/selftest`. If a failure persists, the reason in the new
report is the next diagnostic step. Only Sentinel restarts; configuration and
credentials are preserved. The live server was not changed during development.
